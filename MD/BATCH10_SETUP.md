# Batch 10 setup

Version 0.10.0 adds company campaign reports. On a database with migrations 001 through 009 installed, back up first and apply only supabase/migrations/010_campaign_analytics.sql. New installations apply every migration in numeric order. No new environment variables or external services are required; delivery configuration from Batch 9 still applies.

Open a company workspace and select Reports & analytics. Dates are inclusive calendar dates in UTC, defaulting to the latest 30 days. A report includes runs queued in that range. Outcomes are cumulative as recorded at the report snapshot, even when callbacks occurred after the selected dates. The chart groups by queue date, not callback date. Run links from Delivery queue select the exact queue day and run.

Provider submissions count recipients with saved provider acknowledgement. Confirmed delivery, opens, clicks, bounces and complaints count distinct recipients with matching recorded provider events. Repeated opens and callback replays do not inflate recipient counts. A recipient may appear in several outcome metrics. Failed, skipped, waiting and unknown counts use current queue status. Rates use provider submissions as denominator and show N/A when no submission exists. A quota reservation or request attempt does not imply submission or delivery.

Open/click tracking depends on provider configuration and may include automated activity. Missing callback/tracking data is not proof of no engagement. Local unsubscribe attribution starts after migration 010; earlier confirmation requests still suppress email but cannot reliably be attributed retrospectively to a run. Provider unsubscribe events are included when matched to a delivery. Events still awaiting message reconciliation are excluded until linked.

Any company member can read aggregate reports for that company; Super Admin can read across companies. Anonymous users and other companies are denied by the database RPC. Raw queue recipients, email addresses, unsubscribe tokens and event payloads are not returned. Reports and CSV use the session client, never a client-exposed service key. Read-only reporting remains available for a suspended company, consistent with existing member read access; dispatch restrictions are unchanged.

CSV exports include aggregate run rows, with dates and counts, up to the first 1,000 most recent matching runs. Narrow the date range for larger histories. The page shows 50 runs at a time; totals and chart cover the full selected cohort. The export response states total/exported run counts in headers. Each export is a separate snapshot and can differ from the page as new callbacks arrive. Spreadsheet formula prefixes are neutralized and cells are quoted. UTF-8 BOM supports Excel. The response is private and no-store.

Verification: Node 24, npm ci, npm run lint, npm run typecheck, npm test, npm run build, npm run test:smoke and npm audit --omit=dev. Isolated PostgreSQL tests cover all migrations, metric deduplication, overlapping outcomes, date bounds, pagination and company authorization. Hosted Supabase acceptance, signed-in browser flows and callback integration remain required before production release.

Migration 010 is additive except the service-only unsubscribe function extension. To roll back, restore Batch 9 application and unsubscribe function first, then remove campaign_analytics, the two analytics indexes and unsubscribe_recorded_at only if its attribution history is no longer needed. Prefer a forward fix and preserve backups. Historical migrations are retained.
